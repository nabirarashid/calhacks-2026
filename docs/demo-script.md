# Demo and fallback-video script v3

Target length: 1:50-2:00. Record at 1440x900. The six beats mirror
[`pitch.md`](pitch.md); later-domain shots are gated so the fallback never
overstates the build.

## Preflight claim check

Before recording, write the evidence artifact next to each checked item. An
unchecked item uses the fallback shot.

- [ ] Fin replay completes offline and the visible run is the one being
  narrated.
- [ ] Any baseline comparison is read directly from that run; no remembered
  benchmark is quoted.
- [ ] Live write has a recorded disposable-workspace preview, explicit approval,
  apply, read-back, geometry check, and version result.
- [ ] Generic onboarding returns a reviewed maturity level and capability report
  through the production UI.
- [ ] Bracket artifacts show the declared fidelity, convergence, protected
  interfaces, failure, repair, and final evidence.
- [ ] Any physical bracket claim has a recorded print and load test against the
  prediction.
- [ ] Any heat-sink, Factory Droid, or SpacetimeDB claim is backed by a running,
  committed integration.
- [ ] The CMU Rocket Command wording is written or approved by the named member;
  any direct quote has permission.

## Shot list

1. **0:00-0:15 — Problem.** Title, seed fin, and the goal box. Narrate the
   edit/analyze/check loop and the danger of guessed physics. Do not show or
   mention an unverified physical part.
2. **0:15-0:45 — Fin workflow.** Select the pitch goal, expand its explicit
   constraints and assumptions, then start the curated replay at the rehearsed
   speed. Capture the morphing fin, agent feed, equal-budget curves, and Pareto
   view.
3. **0:45-1:05 — Evidence and authority.** Open the winner review. Pause on the
   parameter diff, requirement margins, geometry state, fidelity, limitations,
   and approval. If the live-write box above is checked, show **Create Onshape
   Version** and the resulting version; otherwise show the engineering report
   and say that live write is not verified for this build.
4. **1:05-1:30 — New-object onboarding.** If the production wizard is verified,
   show the bracket inventory, editable semantics, sourced questions, probes,
   and returned maturity. Otherwise show the maturity-ladder slide and explain
   that generic onboarding is the next product step. Do not use the earlier
   `DiscoveryModal` as evidence of safe onboarding.
5. **1:30-1:50 — Static structures.** If the end-to-end bracket box is checked,
   show failure -> repair and the evidence labels. Otherwise show the FEA spike
   summary briefly and say that only the cantilever kernel validation exists;
   the bracket adapter is not integrated.
6. **1:50-2:00 — Honest boundary.** If the capability report is verified, show
   the duct stopping at inventory-only because no CFD adapter exists. Otherwise
   keep the maturity ladder on screen and say that unsupported physics must
   stop rather than be guessed; the report components are not yet a live
   onboarding flow.

Close on: “Physics does not generalize. The guarded request-to-evidence workflow
does.”

## Recording discipline

- Use replay for the fin unless the live path has passed a fresh rehearsal.
- Keep API keys, document IDs, terminals, browser history, and local file paths
  out of frame.
- Keep fidelity labels and fallback/degradation indicators visible.
- Record one narrated take and one silent screen-only take.
- Keep the final MP4 under 50 MB and copy it to two laptops. `demo/video/*.mp4`
  is intentionally gitignored.
- If a gated beat fails during rehearsal, switch to its written fallback; do not
  improvise a success claim.
